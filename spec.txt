## 1. PROJECT OVERVIEW & SCOPE
CLFIS is a production-grade multimodal retrieval and spatiotemporal matching platform tailored for university campuses. It automates item resolution between "Lost" and "Found" reports using local vision-language embeddings (`google/siglip-base-patch16-224`), alphanumeric OCR token mining, mathematical decay functions, Zero-Knowledge claim validation, and physical handover logging via time-bound cryptographic QR handshakes.

### System Tenets
1. **Multimodal Information Retrieval**: SigLIP shared 768-d embedding space for text $\leftrightarrow$ image, image $\leftrightarrow$ image, and text $\leftrightarrow$ text retrieval.
2. **Context-Aware Scoring**: Spatiotemporal penalization using campus geofences (PostGIS) and exponential time decay.
3. **Zero-Knowledge Security**: Automatic redaction and CSS blurring on high-value items with dynamic security challenge prompts.
4. **Physical Custody Audit**: Cryptographic QR handshakes that verify in-person exchanges and award user reputation (karma).
5. **AIML Rigor**: Dedicated ML evaluation suite measuring Recall@K, MRR, NDCG, and ROC-AUC with synthetic benchmark generators.

## 5. MATHEMATICAL SCORING PIPELINE (`backend/app/ml/scorer.py`)

### Production Hybrid Formula

$$S_{total} = \underbrace{\Big( w_v \cdot S_{visual} + w_t \cdot S_{text} + w_c \cdot S_{cat} \Big)}_{\text{Multimodal Feature Match}} \times \underbrace{\Big( D_{spatial} \times D_{temporal} \Big)}_{\text{Contextual Decay}} + B_{ocr}$$

### 1. Weights & Dynamic Rebalancing

* Default Weights (both reports have photos): $w_v = 0.45$, $w_t = 0.30$, $w_c = 0.25$.
* Single Image / Text-Only Missing Image Weight Rebalancing: If either item lacks an image, set $w_v = 0.0$, $w_t = 0.70$, $w_c = 0.30$.
* Category Similarity ($S_{cat}$): `1.0` if `lost.category == found.category`, else `0.0`.

### 2. Contextual Decays

* **Temporal Decay ($D_{temporal}$)**:

$$\Delta t = \max\left(0, \frac{\text{found.incident\_time} - \text{lost.incident\_time}}{86400 \text{ seconds}}\right)$$


$$D_{temporal} = \exp(-\lambda \cdot \Delta t), \quad \lambda = 0.05$$



*(If $\text{found.incident\_time} < \text{lost.incident\_time} - 1\text{ day}$, penalize with $D_{temporal} = 0.1$).*
* **Spatial Decay ($D_{spatial}$)**:
* If GPS coordinates present: $D_{spatial} = \frac{1}{1 + 0.5 \cdot \text{distance(km)}}$.
* If using Campus Zones: Exact Zone Match = `1.0`, Adjacent Zone = `0.8`, Distant Zone = `0.4`.



### 3. OCR Direct Identifier Bonus ($B_{ocr}$)

* Extract all alphanumeric tokens with length $\ge 4$.
* If $\text{len}(\text{lost.ocr\_tokens} \cap \text{found.ocr\_tokens}) > 0$: $B_{ocr} = +0.25$. Else: $B_{ocr} = 0.0$.

### 4. Decision Thresholds & Normalization

$$\text{Final } S_{total} = \min(1.0, \max(0.0, S_{total}))$$

* $S_{total} \ge 0.80 \rightarrow$ `HIGH_CONFIDENCE` (Instant notification + ZK Challenge triggered).
* $0.55 \le S_{total} < 0.80 \rightarrow$ `POTENTIAL` (Listed in dashboard "Suggested Matches").
* $S_{total} < 0.55 \rightarrow$ `DISCARD` (Not persisted to database).

## 6. AIML EVALUATION SUITE (`ml/src/evaluation/`)

To validate system performance scientifically, the `ml/` package provides benchmark runners:

### Metrics Measured (`metrics.py`)

1. **Top-K Recall ($\text{Recall}@K$)**: Proportion of true lost-found matches found within top $K$ retrieved items:

$$\text{Recall}@K = \frac{|\text{Relevant Candidates} \cap \text{Top-}K|}{|\text{Total Relevant Candidates}|}$$


2. **Mean Reciprocal Rank (MRR)**: Evaluates where the correct match appears in the ranked candidate list:

$$\text{MRR} = \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$$


3. **Normalized Discounted Cumulative Gain ($\text{NDCG}@K$)**: Measures ranking quality with relevance grades.

### Benchmark Command

```bash
python ml/src/evaluation/run_eval.py --dataset ml/data/processed/campus_test_pairs.json --top_k 5

```

## 7. BACKEND API SPECIFICATION (FastAPI)

### Authentication (`/api/auth`)

* `POST /register`: Registers user with email domain validation (e.g., `@college.edu`).
* `POST /login`: Issues JWT bearer token containing `sub` (User ID) and `role`.
* `GET /me`: Returns profile and `karma_score`.

### Item Lifecycle (`/api/items`)

* `POST /report`: Accepts `multipart/form-data` with up to 3 images, description, zone, timestamp, and category.
* Saves images to disk.
* Returns `201 Created` immediately.
* Dispatches non-blocking match execution via `asyncio.to_thread` in FastAPI `BackgroundTasks`.


* `GET /feed`: Returns paginated open items. Automatically redacts image paths of high-value items if requester is not the owner or an admin.
* `GET /{item_id}`: Single item detail view.

### Zero-Knowledge Claims & Handshake (`/api/claims`)

* `POST /challenge/create`: Initiates claim verification prompt.
* `POST /challenge/respond`: Claimant submits descriptive answers.
* `POST /challenge/approve`: Finder or Security Desk approves answer; issues signed 15-minute JWT QR Token.
* `POST /handshake/verify`: Finder or Admin scans QR token; marks status as `RESOLVED` and awards $+25$ Karma to finder.

### Admin & Vault (`/api/admin`)

* `GET /vault/unclaimed`: Retrieves items older than 45 days.
* `POST /vault/process`: Bulk updates status to `UNCLAIMED_VAULT` for auction or donation logging.

## 8. FRONTEND SPECIFICATION (Next.js 14 App Router)

### Pages & User Flows

1. **Public Feed (`/feed`)**: Instant search bar with category badges and campus zone filters. Sensitive items display a styled `backdrop-blur-md` overlay with a "Claim & Verify" action button.
2. **Report Lost / Found (`/report/lost`, `/report/found`)**: Multi-image drag-and-drop dropzone with preview, zone dropdown, and high-value toggle.
3. **Printable Notice Generator (`PosterGenerator.tsx`)**: One-click generation of a clean PDF poster via `jsPDF` containing item photo, details, and dynamic QR link for campus bulletin boards.
4. **Interactive Claim Portal (`/claims/[id]`)**: Step-by-step verification wizard (Question Prompt $\rightarrow$ Awaiting Finder Approval $\rightarrow$ Present Handshake QR).
5. **Admin / Security Handshake Scanner (`/admin`)**: Integrated webcam QR scanner powered by `html5-qrcode` to verify claimant tokens during physical item pickup.
